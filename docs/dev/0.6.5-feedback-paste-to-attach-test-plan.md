# 0.6.5 — Feedback bubble paste-to-attach: manual test plan

Paste an image from the clipboard into the feedback bubble's "Share your feedback…"
box and it becomes an attachment, with no save-to-disk-then-browse round trip.

**Files changed**

| File | What |
|---|---|
| `app/javascript/llamapress/paste_to_attach.js` | New — clipboard → file-input logic |
| `app/javascript/llamapress/feedback_bubble.js` | Wires the textarea to the file input; attachment preview (thumbnail + filename + remove), replacing the truncated label next to the paperclip |
| `vitest.config.js` | Adds a `llamapress` → `app/javascript/llamapress` alias so specs can import importmap-style bare specifiers |

Both JS files are duplicated into `Leonardo/rails/app/javascript/llamapress/` (Leonardo
mounts `./rails/app`, so that copy is what actually runs in dev). They are in sync.

## What automated tests already cover

`spec/javascript/llamapress/paste_to_attach.test.js` (12) +
`spec/javascript/llamapress/feedback_bubble_paste.test.js` (5) — 20 examples with the
suite, all green:

| Behaviour | Covered |
|---|---|
| Pasted image lands on the file input | ✅ |
| Filename stamped `pasted-image-<ts>.<ext>` | ✅ |
| `image/jpeg` → `.jpg`; unknown type → `.png` | ✅ |
| Multi-image paste gets unique `-1`, `-2` suffixes | ✅ |
| Plain text / HTML / PDF paste ignored, default not prevented | ✅ |
| `preventDefault()` on an image paste | ✅ |
| Single-file input replaces; multi-file input appends | ✅ |
| Preview updates on paste (no `change` event fires) | ✅ |
| Pasted image gets a thumbnail, not just a name | ✅ |
| A real filename on the clipboard is kept as-is | ✅ |
| × removes the attachment and hides the preview | ✅ |
| No clipboard data / null `getAsFile()` / missing input → no crash | ✅ |

I mutation-checked these: with the paste handler removed, the behavioural tests fail.

**Not covered — this is what the manual pass is for.** Everything below the JS logic:
the real OS clipboard, real `ClipboardEvent`/`DataTransfer` in a real browser,
cross-browser differences, and the actual upload landing on the feedback record.
happy-dom fakes the clipboard, so a real-browser regression would not be caught.

## Setup

- Dev app: https://rails-llamapress-dev.llamapress.ai — log in as a normal user.
- The bubble only renders when `feedbackBubbleEnabled` **and** `userLoggedIn`; if you
  don't see the grey circle bottom-right, you're logged out.
- **Hard-refresh** (Cmd/Ctrl+Shift+R) — importmap serves the JS file directly and a
  stale cached copy will silently test the old code.
- Keep the browser console open. A JS error here fails silently.
- Have ready: a screenshot on the clipboard, a JPEG, a copied block of text, a
  copied PDF file, and an image copied from a web page (right-click → Copy image).

## A. The core path

| # | Step | Expect |
|---|---|---|
| A1 | Take a screenshot to clipboard (Cmd+Ctrl+Shift+4 / Win+Shift+S / PrtScn) | — |
| A2 | Click the bubble → click into the "Share your feedback…" box → Cmd/Ctrl+V | A thumbnail of the image appears with its filename underneath and an × to remove it — same shape as the camera-icon screenshot preview. A clipboard screenshot has no name, so it reads `pasted-image-<numbers>.png`; a **copied image file** shows its real name |
| A3 | Look at the textarea | **No junk text pasted in** — the box stays empty |
| A4 | Type "testing paste" and click **Send** | "Thanks for your feedback!" then the panel closes |
| A5 | Open `/llama_bot/feedback` → newest item | The image is attached and opens/renders correctly |

## B. What must NOT change

| # | Step | Expect |
|---|---|---|
| B1 | Copy a paragraph of text, paste into the box | Text appears in the textarea as normal; no attachment |
| B2 | Copy a PDF file in Finder/Explorer, paste into the box | Nothing attaches, no console error |
| B3 | Paste text, then paste an image, then type more | Text is intact, image attached, typing works |
| B4 | Click the paperclip and browse to a file the old way | Still works; an image shows a thumbnail + its name, a PDF/doc shows just the name |
| B5 | Take a screenshot with the **camera icon** (annotator) | Still works, image preview thumbnail still appears |
| B6 | Record a video with the video icon | Still works |
| B7 | Select an element with the cursor icon | Still works |

## C. Edge cases

| # | Step | Expect |
|---|---|---|
| C1 | Paste an image, then paste a **different** image | Second replaces the first; label shows the new name (input is single-file — see Known limitations) |
| C2 | Paste an image, then click paperclip and browse a file | Browsed file wins; label updates |
| C3 | Right-click an image on a web page → Copy image → paste | Attaches (this clipboard also carries `text/html`; the image must still win) |
| C4 | Paste a JPEG | Filename ends `.jpg`, not `.jpeg` |
| C5 | Paste an image, click **Send** with the textarea empty | "Please enter some feedback" — description is still required |
| C6 | Paste a large image (~5–10 MB) | Attaches; note how long Send takes; confirm it lands on the record |
| C7 | Paste with focus **outside** the textarea (e.g. on the panel background) | Nothing attaches — by design, the listener is on the textarea only |
| C8 | Open bubble, close it, reopen, paste | Still attaches (listener survives the panel toggle) |

## Known limitations (expected, not bugs)

1. **A clipboard screenshot has no filename.** Browsers hand it over as a nameless
   bitmap, so it still shows as `pasted-image-<timestamp>.png` — there is nothing
   better to display. An image *file* copied from Finder/Explorer keeps its real name.
   The thumbnail is what tells you which image you attached either way.
2. **Single-file input.** A paste replaces whatever was attached before; you can't
   paste two images into one feedback item. The underlying helper supports multi-file
   inputs already, so this is a one-line change if you want it.
3. **The textarea only.** Pasting while focused elsewhere in the panel does nothing.

## Running the automated tests yourself

LlamaPress-Simple's `spec/` is not mounted into the dev container, so `docker compose
exec llamapress npm test` runs the *image's* copy, not your working tree. To run the
working tree:

```bash
cd ~/dev/LlamaPress-Simple
npm install          # no node_modules on the host yet
npx vitest run spec/javascript/llamapress/
```

Note the container's baked `vitest.config.js` predates the alias added here, so these
specs only pass against a config that includes it — i.e. this repo's working tree, or
a freshly built image.
